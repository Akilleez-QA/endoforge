# EF-02 / WP06

Demand: the owner's EF-02 packet, supporting audit-ready evidence and job handoff on the jobs board. Happy path: admit the task and inputs, freeze the evaluator, then evaluate a candidate with that durable evaluator identity. WP06 in `docs/execution/WORK-PACKAGES.md` and R11's frozen-evaluator discipline govern this packet. `forge/endoforge/AGENTS.md` is absent in this checkout.

Reuse: EF-01's canonical encoding, append-only SQLite transaction and chain verification provide the store. No separate mutable object directory is needed: frozen file bytes are hex-encoded inside the ledger. The evaluator identity hashes the complete record data, including confirmation and qualification; `freeze.digest` hashes the canonical bundle of relative file names, bytes, configuration, residual and invariant version. File modes and empty directories are not execution inputs; adapters must consume the supplied bundle.

From `forge/endoforge`, run `python3 -B -m tools.ledger.frozen freeze LEDGER TREE MANIFEST.json`. The manifest supplies the keyword arguments to `FrozenEvaluators.freeze`: task, admitted_input, confirmed_by, qualification, synthesis_context, configuration, residual and invariant_version. The synthesis context has id, candidate_blind (`confirmed`) and inputs (durable task/admitted-input ids, including the selected admitted input). Optional revision has of, reason (`specification_correction` or `independent_qualification`) and evidence (an admitted-input id). Outcome reasons and extra outcome fields fail schema validation.

`FrozenEvaluators.evaluate(tree, receipt, judge, **components)` checks the current bundle against the durable hash, writes a running receipt, then calls `judge(bundle)` with the stored snapshot. The judge returns `(outcome_state, observations)`; the engine appends the finished receipt. The receipt's precommit oracle_version must be the bundle digest. The initial receipt uses the supplied id plus `:started`. Judge exceptions leave that running record as evidence; recovery remains outside EF-02. `require_frozen` exposes the same pre-evaluation gate to other adapters.

The ledger transaction rejects changed evaluator content after either failed or failed_with_test_concern for the task, including changes using another evaluator identity or admitted-input identity. Before failure, revisions must name the latest evaluator and admitted evidence. A new task is a new scope. Existing EF-01 inline records remain readable without changing fixtures; the new engine refuses to execute these legacy, unhashed records. Existing independent campaign runners are not retrofitted by this packet.

Trust boundary: the engine supplies frozen bytes, but adapters must actually judge with them. This is not a sandbox against a malicious callback or database owner. Candidate-blindness validates declared input identities, not the semantic truth of their text or undisclosed context. Qualification and confirmation are recorded attestations.
