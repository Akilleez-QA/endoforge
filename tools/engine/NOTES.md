# EF-05 / WP09a universal gates

The owner's EF-05 packet authorizes this worker implementation in the supplied stack; publication and Git mutations are reserved to the orchestrator. The jobs-board connection is audit-ready evidence and checking readings: rejected capabilities need an attributable check before use. The governing acceptance source is WP09 in `docs/execution/WORK-PACKAGES.md`; this checkout has no separately defined WP09a. This packet implements its five universal gates, positive/negative controls, identical replay verdicts and first-failure attribution. Residual evaluation, Pareto ranking and finalist rounds remain outside EF-05.

The port is trusted host tooling, never candidate code. `runUniversalGates(input, port)` accepts version 1, an immutable candidate identity, contract, probe cases, limits and an explicit allowedEffects list. Its structured result contains passed, firstFailure (one check or null) and only the executed gate results, each with check, passed and reason. Order is schema, interface, bounds, determinism, forbidden_effects. Exceptions fail the active gate. No clock or generated identity enters verdicts.

Contract and signature checks reuse `tools/factory_quality/index.mjs`; its canonical encoder compares signatures and outcomes. The closed gate envelope adds validation for limits, cases and evidence. Values must be plain JSON, finite and without negative zero; callers must explicitly encode exceptional numeric probe inputs. Probe inputs may include deliberate invalid values to exercise refusals. This is the existing typed-signature contract, not arbitrary JSON Schema or a WIT implementation.

Port methods may be synchronous or asynchronous. `describe(candidate)` returns an artifact-observed signature in the existing factory-quality format. `run(candidate, cases, limits)` creates a fresh isolated instance, enforces wallMs, memoryBytes and fuel, and returns `{status, outputs, usage, effects}`. Successful status is completed. Outputs follow case order and contain caseId plus either value or error `{path, reason}`. Usage contains all three measured resources. Effects are host-observed attempted effect names, including denied attempts. `scanEffects(candidate)` returns static capabilities/import effect names. Missing methods or evidence fail closed. The port must pin all operations to the same candidate bytes and must never perform candidate-requested effects while probing.

The bounds gate collects two fresh runs sequentially, stopping immediately on a failed run; determinism compares their values, complete refusal details and effects, excluding measured usage. Static and runtime effects are checked against the explicit allowlist. A pass covers these probes only. This engine judges evidence; it does not implement a sandbox, certify a port's measurements, freeze an evaluator, run residuals or authorize promotion. EF-02 remains the owner of evaluator freezing.

Findings: existing X1 gates are a CLI coupled to compilation and promotion; importing them would execute that workflow. The factory-quality validators are reusable without side effects. Its standalone test script writes historical campaign results, so this packet uses new controls that call the validators without running that writer. No existing fixtures or expected results are edited.

Review lesson: copying the policy after awaiting schema validation admitted caller mutation between validation and execution. Cost: one review revision and a full-suite rerun. Closed by retaining the schema gate's validated snapshot; the new caller-mutation control proves an allowlist change cannot authorize an effect mid-run.
