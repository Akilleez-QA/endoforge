# Independent next-50 choices audit

Audited 18 October 2026 during implementation. This audit changed no implementation, global configuration, old probe receipts, or other lanes' files. Bounded probes used only this audit directory. No model calls were made. The implementation changed while findings were handed to the implementing parent; earlier adverse receipts remain historical evidence, and later rechecks identify which findings were fixed. This is not N50 qualification of the complete factory: N20 and its dependent live workflow remain blocked.

Review first: the initial implementation could publish a wrong-question candidate, treat fuel exhaustion as an expected refusal, and invalidate a pressure test with unrelated SI-prefix evidence. The parent corrected these decisions; independent rechecks below confirm rejection of those exact cases. The remaining architecture needs particularly careful wording around request recovery, runtime-derived refusal paths, and source-bundle publication.

### Remaining gaps and acceptance limits

- **Full workflow recovery remains unqualified.** `tools/factory_campaign/pipeline.py:25` writes stage state in place; `tools/factory_runtime/core.py:23` writes mutable control files in place, and `tools/factory_runtime/scheduler.py:32` uses that overwrite path for queue state. A controller or storage failure during a write can leave unreadable JSON; fsync after the write does not make replacement atomic. The immutable attempt journal and no-overwrite publication mechanism have a stronger boundary, but do not establish recovery of the whole intake/eval/generation workflow. Keep N34/N42 incomplete until crash boundaries across those stages are exercised, with a recoverable previous complete state or explicit unresolved journal entry. No disk-power-loss experiment was performed.

- **Refusal path is supplied by the expected test, not the module.** Current `pipeline.py:122` labels an unreachable trap with `c.errorPath`; a pure numeric WASM trap itself carries no input-path explanation. This is a reasonable one-input convention, but does not establish independently observed attribution of a misleading multi-input refusal. Qualify N18/N31 only for that narrow convention, or derive/validate path independently from the typed input validator and structured runtime error protocol.

- **Authentication and credential scope remain separate facts.** Temporary token copies preserve subscription-account authority (`tools/factory_campaign/models.py:49`); their filesystem visibility is temporary, not newly narrowed provider permissions. The runtime owner reports final namespace/capability hardening occurred after the successful auth probes. A final-boundary authenticated flow must be replayed before a comprehensive N27 auth claim. No audit model turns were spent; no fallback to paid APIs occurred.

- **Provider-origin restriction is narrower than an application firewall.** The proxy constrains CONNECT names, pinned public IPs and now TLS SNI. It cannot inspect encrypted HTTP authority, provider application paths or credential use. State that exact route boundary; do not claim that this prevents every provider-mediated action. Host/LAN/metadata-IP denial is a different and directly testable property.

- **Broad route labels do not imply broad execution backends.** `factory_quality.routeRequest` recognizes lookup/text/workflow categories, while `factory_campaign.pipeline` generates f64 numeric code and initially prompts for affine one-input procedures. No generic workflow/text-check capability quality claim follows. N20 is blocked by missing Claude authentication, so N31/N32/N38/N42 and experimental dependents are not qualified by deterministic numeric probes.

- **Checkpoint mechanism is not campaign restore.** `factory_portability/checkpoint.py:16` validates required metadata containers and inventory, not stage semantics or fencing a running campaign. Encryption and hostile-archive controls qualify the packaging mechanism. `portability/summary.json` correctly separates the real second-host offline replay (19 candidates/242 tests) from N40's still incomplete partly-completed live campaign recovery. Do not substitute the former for the latter.

## Choices ledger

No entry requires an immediate user-only decision. Provisional choices below remain reversible; none authorizes production adoption.

### Unsound choices, corrected during implementation

**A1 — Allow separately valid request and eval documents to stand for one job.** When the intake said “always return 42” but the tests described temperature conversion, both documents passed their own schemas. The code then followed the tests and passed every gate while answering the wrong request. The plan specified one manifest but did not spell out cross-file identity checks. This reaches every future import and recovery path. **Verdict: unsound. Correct decision:** one exact normative request and signature must be bound through intake, frozen evals, candidate and publication, and checked again before trusted execution. Parent implemented and audit rechecked this. **Confidence: high.**

**A2 — Treat any failed execution as proof of proper refusal.** An invalid-input test expects the candidate to refuse; the old adapter treated a timeout or exhausted fuel (the instruction budget that stops endless work) as that refusal. The plan did not prescribe how the runtime reported different trap kinds. Future failure rates and guard mutations would inherit the misclassification. **Verdict: unsound. Correct decision:** only a known deliberate refusal signal can satisfy refusal expectations; bounds and host failures remain execution failures. Parent corrected this, including exact diagnostic matching; a real fuel exhaustion control now rejects. **Confidence: high.**

**A3 — Interpret registered numerical evidence without checking its subject.** A trusted file established that 1,000 metres is 1 kilometre. The first resolver compared its result 1 to any test's expected number, including an oxygen-pressure case. Its trusted registry proved the bytes were selected independently, but did not prove they answered the same question. This gap affected all future challenges. **Verdict: unsound. Correct decision:** establish the same function, inputs and units before using evidence to contradict a test. Parent corrected the narrow resolver; unrelated evidence now rejects. **Confidence: high.**

**A4 — Match only part of the executable interface.** An implementation could add a required argument or shrink its declared domain while retaining the expected argument names and units. Earlier checks accepted it. The plan asked for compatibility but did not define equality. **Verdict: unsound. Correct decision:** require the complete frozen interface in the current prototype; any future compatibility relaxation needs a separately proven rule. Fixed and independently rechecked. **Confidence: high.**

**A5 — Reuse capabilities by interface alone.** Two requests may both export `convert(x)` with identical units while applying different normative policies. Earlier identity had no request text, so future tasks could inherit a calculation they never requested. **Verdict: unsound. Correct decision:** semantic requirements belong in reuse identity, alongside interface, assumptions and references. Exact normative text is the current conservative implementation. Rechecked. **Confidence: high.**

### Sound choices, least-confident first

**A6 — Publish the verified source bundle rather than only compiled WASM.** The runner accepts an expected output hash known before a worker starts. A newly compiled binary's hash is not yet known. The parent captures and bounds the binary, runs trusted Docker gates, then publishes the canonical source bundle whose identity was already known; local consumer experiments use the captured binary separately. The plan did not choose the publication representation. This enables reconstructing the candidate, but future consumers must retain the compiled-module identity and toolchain identity and revalidate recompilation. **Verdict: sound for an experimental source catalogue, not a claim that the catalogue directly contains a ready-to-run verified binary.** **Confidence: medium.**

**A7 — Start with one-input numeric procedures and exact arithmetic challenges.** A broad request taxonomy can exist before every backend does. The implementers chose repeatable affine/threshold numeric examples and one exact-rational source-backed challenge to establish boundaries. An alternative would be broad model generation before the ruler is qualified. The plan delegated implementation details but did not explicitly limit the first API's generality. This constrains which requests may be called executable. **Verdict: sound only while unsupported/unqualified domains stay explicit and counted.** Extend by new qualified backends, not by relabelling present fixtures. **Confidence: medium.**

**A8 — Choose explicit conservative model limits.** The user authorized executing 50 items without specifying spending or model-turn ceilings. The implementation precommitted 60 turns, a soft 750k token budget and hard 1.5M token ceiling, with lane allocations and subscription-only execution. This can stop a useful run early, but keeps failed measurements visible and avoids implicit paid-provider substitution. **Verdict: sound, reversible by a later explicit experiment budget; no statistical power claim follows from these numbers.** **Confidence: medium.**

**A9 — Keep output checking separate from execution authority.** The quality library receives observed outputs rather than launching arbitrary candidate code itself. If a generator supplied those observations it could simply write the answers. The trusted pipeline instead compiles and runs the candidate, constructs the observations, then invokes the checker. The plan did not specify module separation. This makes the checker reusable but establishes a load-bearing host-only trust contract. **Verdict: sound while every publication path independently executes the candidate; the actual forged-success/wrong-value probe confirms this path.** **Confidence: high.**

**A10 — Prefer byte-pinned, exact-text reuse over semantic guessing.** Including literal normative request text means harmless paraphrases cause a miss. That costs extra generation but prevents interfaces with different meanings from colliding. The plan did not prescribe a semantic equivalence engine. **Verdict: sound conservative default; future semantic reuse must bring its own proof and separate receipts.** **Confidence: high.**

**A11 — Use age-encrypted inventory checkpoints and separate toolchain bundles.** Campaign state and source files are inventoried, hashed and encrypted; large compiler/runtime distributions travel separately with their own identities. The plan required encryption and dependency identity without selecting a format. When restoring, the destination authenticates the archive before extraction and validates all member paths and types before publishing the restore directory. **Verdict: sound mechanism choice with explicit Linux/platform and caller-owned quiescent-staging limits.** It does not decide whether state is semantically resumable. **Confidence: high.**

**A12 — Keep the final result as no evidence when model prerequisites fail.** Claude returned authentication failures while Codex produced development evaluator outputs. Combining deterministic hand-built fixtures with one family would produce a runnable demonstration, but would not satisfy the declared two-family qualification. The parent continued offline debugging and kept broad live/comparative execution gated. This constrains N20 and every dependent item. **Verdict: sound.** A prerequisite failure is retained evidence, not a successful substitute. **Confidence: high.**

**A13 — Preserve narrow credential and second-host claims.** A temporary copy of an account token is not a provider-issued role restriction; a different-host toolchain replay is not resuming an interrupted live campaign. The implementation retained the token-scoping limitation and withheld N40 completion while still using the real second host for offline bootstrap. **Verdict: sound.** These distinctions keep future adoption from inheriting guarantees that were never tested. **Confidence: high.**

The parent replaced pipeline metadata overwrites with atomic temporary-file replacement (`tools/factory_campaign/state.py:17`) and stage snapshots with append-only numbered event files (`:39`). `recover` (`:54`) checks the event chain and rebuilds missing, stale or truncated snapshots from the newest complete event. **A14 — Store durable stage events separately from a replaceable convenience snapshot.** When a generator finishes and the controller dies while updating its current-state file, an in-place JSON file can become unreadable. Future readers must treat the event sequence as the recovery source, while an unreadable or broken sequence remains explicitly unresolved. **Verdict: sound for the tested local process-crash metadata boundary.** It does not decide whether restarting a model request repeats a remote side effect; those stages still require their own attempts and reconciliation. **Confidence: high.**

**A15 — Reject unsupported execution shapes before allocating work.** The general intake vocabulary includes workflow and text requests, but the implemented compiler path only handles one numeric argument and a numeric result. Previously the vocabulary could be mistaken for backend support. The parent now rejects workflow classes and multi-input signatures before creating the job, so future callers receive an explicit unsupported outcome rather than a misleading failed numeric attempt. The plan left the first backend's breadth to implementation. **Verdict: sound conservative scope; retain rejected requests in outcome denominators.** Extending this boundary requires a separately qualified backend. **Confidence: high.**

The earlier expected-test-derived refusal-path limitation remains explicit: a single numeric argument with an unreachable trap supplies a refusal convention, not a general executable explanation of which argument caused a refusal. N20 and dependent full-workflow/statistical/adoption claims remain unqualified while Claude authentication is unavailable.
