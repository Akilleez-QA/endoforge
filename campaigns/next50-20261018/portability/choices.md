# Portability decisions

- age X25519 recipient encryption uses an existing authenticated encryption implementation. We did not implement a cipher/MAC composition or copy model credentials. Ephemeral test identities stay outside repository and are deleted. Real cross-host identity is passed only via SSH stdin.
- Checkpoint input is an explicit quiescent allowlist. All regular payload bytes are inventoried; symlink/hardlink entries are refused, even when a symlink points internally. Toolchain distributions containing legitimate internal symlinks travel in a separate hash-pinned nonsecret archive and are checked again after transfer. Generic arbitrary tar extraction is never the checkpoint importer.
- Linux renameat2 NOREPLACE was added after identifying a destination check/rename race. v1 evidence retained; v2 implementation and hashes precede rerun.
- The fresh bootstrap copies the complete npm distribution as versioned runtime content, but no prior compiler node_modules or cache. A new cache is populated from the public registry using the original compiler lockfile and disabled scripts; offline replay reconstructs into a different empty directory. Exact npm content is pinned rather than relying on a mutable installed executable alone.
- Wasmtime was supplied by the runtime lane with recorded v49.0.3 executable SHA256. Entire executable is included/pinned, and known-good/fuel-exhaustion/trap smoke checks passed on both hosts.
- Node22.18.0 was provisioned from the prior pinned image-extracted executable; compiler source lockfile remains unchanged. This is a standalone portable runtime distribution, not a clean OS/compiler-source bootstrap or independent provenance attestation.
- fieldops is a genuinely different physical tablet, evidenced by different hashed machine IDs and prior authorized host identity. Existing sudo-n Docker access was inspected read-only. Worker replay used user bubblewrap with networking disabled, avoiding system daemon changes and large image transfers. No packages, services, desktop state or application files changed.
- Historical 19-candidate replay qualifies toolchain content and output parity only. N40 remains incomplete until a real integrated partly completed campaign resumes after its actual paired evaluations/generator on the remote host; historical or synthetic replay is insufficient.
- Receipts retain absolute paths as exact command evidence. Public report describes artifact identities without private request text; payloads must remain allowlisted and no arbitrary credential scanning guarantee is claimed.

- Real-transfer preflight caught SSH stdin reopening failure before any campaign transfer. age identity `/dev/stdin` was replaced by its supported `-` stdin stream. Correct/wrong-key/tamper remote controls passed in attempt02; initial script/failed receipt are retained. No identity file was stored remotely; both attempts' own synthetic ciphertexts were cleaned.

- N40 used the actual new `dev-affine-01` Codex-generated job with independently written Codex/Qwen evals and a `portable-consumer` stage already pending in its authoritative state. It did not roll back completed stages or relabel historical artifacts as fresh generation. The four independent consumer cases were frozen before packaging. Source completed stages include trusted Docker verification/publication; the pending remote consumer itself runs pinned Wasmtime with no network or model authentication. This is a genuine operational campaign resume with narrow stage scope, not a remote live-model authentication claim.
- Retain the real age identity privately outside the repository, mode0600, so the encrypted checkpoint remains recoverable. Only its custody path/public recipient are in receipts. Successful recovery copied its exact publication and attempts back before removing all owned remote staging. Decrypted local staging stays ignored; public evidence contains ciphertext, provenance hashes and numeric execution outcomes.
- Source and destination publications match byte-for-byte, including source/frozen input hashes. Two independent resume invocations on each host produce one publication plus reuse; attempts remain separately recorded. The resumed state is returned to the parent for trusted acceptance into the original campaign. Portability did not modify another lane's job state.
