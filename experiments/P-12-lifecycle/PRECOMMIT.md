# P-12: trusted container lifecycle and attempt evidence

Proposed 18 October 2026, before measurement. Addresses P-09 choices audit's missing timeout cleanup, attempt reuse, interrupted controller and promotion qualification. Recorded (probe), one host, no models.

Use P-09's immutable image ID, no pulls/builds, network, sockets, host credentials or worker host-write mounts. Each attempt has a unique named container, non-root, dropped caps, read-only root, private 8 MiB output tmpfs, 64 MiB scratch, 1 CPU, 128 MiB memory, 32 processes. The trusted host snapshots a small frozen input after validating its SHA-256, and owns validation and atomic publication. Only exact expected artifact content passes. Container logs, inspect state and removal verification must precede sealing an attempt. Existing attempt names must fail before writes; duplicate job publication must fail atomically.

Run success, worker exit 7, hung worker timeout, subprocess controller SIGINT, absent output, existing-attempt reuse with tree digest unchanged, tampered frozen input and duplicate publication. Assert expected result, no container left for every launched attempt, and only one publication. Raw commands, terminal states, stdout/stderr, artifact hashes, environment before/after and summary retained. No candidate/campaign files changed. Record implementation and precommit hashes before measurement. Any missing cleanup/evidence, unexpected publication or source mutation is failure. Stop if <5 GiB disk or 5 minutes elapsed. No system Docker changes. Tests are deterministic fault injection, not live-agent recovery.

Limits: no SIGKILL, daemon/host failure or power-loss guarantee; no cross-host restore, encrypted archives, hostile-kernel escape, concurrency throughput or eval-quality claim. Unique attempts require trusted host ownership; chmod is accidental mutation protection, not security against the host user. Worker-controlled output is copied only after terminal state; expected SHA is host-owned.
