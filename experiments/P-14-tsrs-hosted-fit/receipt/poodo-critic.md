## Final findings (preserved substantive memo)

P-14 justifies retaining published @tsrs/wasm as a promising integration candidate. It does not justify adoption or making hosted fit the next priority.

Warm medians improve 34.8 -> 9.46 ms and 80.9 -> 32.4 ms Node, and 37 -> 10 ms and 86 -> 31 ms workerd. Planted diagnostics and clean controls match. Linear memory rises roughly 45/52 -> 96/101 MiB. These describe exact artifacts, bridges, runtime versions and two deterministic projects; see receipt/summary.json arms and cells, and corresponding raw cells arrays.

Limits:

- Local workerd with --max-old-space-size=128 provides neither real Cloudflare enforcement nor isolate heap accounting. Process RSS cannot resolve the remaining allowance.
- Eighty repetitions per runtime repeat two projects rather than eighty independent compatibility cases. Negative coverage is one assignment-error class. Emit, incremental and library checking are disabled in the main workloads. Emit/UTF-16 controls are Node-only.
- Different compiler/library versions, build profiles and bridges change together. Fixed old -> new order and a shared machine confound precise attribution. A substantial integration effect is credible here, not a portable multiplier.
- Cold is first invocation after compiling the module; no application-startup or factory-throughput result.
- Savings of roughly 25–55 ms/check lack a denominator showing accepted-capability latency, cost or failure-rate significance.

Strongest alternative priority: useful trustworthy output on representative real tasks, with frozen independent evaluations and end-to-end cost breakdown. The current five-request synthetic campaign has zero paired completion difference, two holdouts, an evaluator arithmetic error and resolver implementation deviation; its DECISION.md withholds real refrigeration utility and reliable unconstrained-eval claims.

Strongest disconfirmation of deferral: the gain appears in both runtimes with matching planted outputs and lower process RSS; new gzip module-plus-glue is only 2,844,876 bytes. A small compatibility/hosted gate could be inexpensive. Rejecting tsrs would be unjustified.

Suggested discriminator: representative frozen end-to-end packet records checker time/count, evaluation validity, accepted output and total latency, with a prospective compiler-share or hosting requirement trigger. If compilation constrains that packet or hosting is explicit, test realistic compatibility and actual hosted enforcement; otherwise defer.
