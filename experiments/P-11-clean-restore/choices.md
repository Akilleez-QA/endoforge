# P-11 execution choices — 18 October 2026

- Restore archived, already compiled/evaluated candidates instead of invoking models: this probe owns P-09 U2's independent recovery gap; live generation is separate parallel work. Does not establish live campaign recovery.
- Keep source archives/receipts and copy locally. Verify existing archive SHA-256 and every restored input hash; no original checkout mounted into workload containers. Original receipts are read by trusted comparison logic only.
- Derive image ID from the archived config's SHA-256, inspect that content ID after load, and run by that ID. Avoid relying on the original tag or daemon cache.
- Use vfs with snapshotter disabled: new image roots are inspectably empty and independent of original content storage. Performance differs from the system daemon and cannot be directly compared as a backend benchmark.
- First attempt omitted explicit containerd selection. Docker 29 automatically used the system containerd despite unique Docker data/exec roots. This was an execution choice error: vfs archive parity remains useful but does not qualify a fully isolated runtime. All first-run receipts retained; no system daemon, images or unrelated containers intentionally modified. Cross-runtime event traffic was observed; no host-network causal claim is made.
- Second attempt explicitly created private containerd, but the longer exec-root made Docker's Unix callback socket path exceed platform limits. It failed before load/workloads and both owned processes/stores were cleaned. Preserve that failure rather than overwrite it.
- Third attempt uses short local state paths, a separate containerd root/state/socket and namespace, and launches dockerd in a new network namespace. This addresses runtime sharing and possible host bridge interactions. No privileged workload containers or Docker sockets inside workers.
- Negative control flips one byte in an owned input archive copy. Trusted SHA validation rejects it before extraction or daemon launch. This tests enforced integrity checking against accidental corruption, not authenticity against an attacker who can replace the trusted digest.
- Retain all attempts and select the third as authoritative. run.sh points to that immutable attempt and refuses repeats without changing its receipts. Setup uses only existing packages; no dependencies downloaded. Original exact runner hashes remain valid for each attempt.
