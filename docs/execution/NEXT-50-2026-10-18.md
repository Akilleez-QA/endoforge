# Endoforge: next 50 work items

> Written 2026-10-18 from the recorded quality findings, active DEC-78–DEC-81 and P-09 through P-13 qualification. All work and acceptance conditions below are **Proposed**. No execution, budget allocation, production adoption or campaign result is implied by this plan.

## Purpose

Turn the isolated probes into one recoverable factory that produces useful capabilities, then measure improvement on genuinely fresh requests. Packaging is supporting work. The binding quality problems remain hidden assumptions, missing inputs, weak evals and inconsistent reference values. This plan supplements the earlier WP01–WP32 programme; its N identifiers are an ordered near-term backlog, not replacement work-package numbers.

## Summary

- Exactly 50 actionable items, each with a deliverable, completion check and prerequisite IDs. Item order is a review order; explicit prerequisites determine execution order.
- Keep authenticated makers in host bubblewrap, trusted verification in pinned Docker, and orchestration/publication on the host. Do not pursue privileged nested bubblewrap or install TX9 as part of this backlog.
- Two request-blind model families write executable evals. Reference data comes through a consuming-project provider, independently checked against candidate calculations. Reviews and consumers remain agentic.
- Integrate and qualify a small complete workflow before broad model runs. Preserve the failed probe attempts, existing application boundary and cancelled capability integration.
- Run quality and control-plane work in parallel. Cross-machine portability is a separate track and does not block local quality claims that explicitly remain local.

## Baseline and boundaries

**Recorded (probe):** P-10 supplies real authenticated generation/evaluation and Docker verification of the same outputs, with an original orchestration failure preserved. P-11 proves archive-only recovery of frozen replay in an empty private runtime on this host. P-12 qualifies lifecycle faults and externally triggered crash reconciliation, not an installed supervisor. P-13 reconstructs dependency content and distinguishes workload time from invocation overhead. None is a complete production campaign runner or proof of improved fresh-request utility.

**Proposed completion rule for every item:** retain source/version hashes, runnable validation or inspectable schema examples, terminal outcomes and limitations. Model measurements require a hashed precommit, stage-level token/wall accounting, declared retry limits and subscription-only execution. Failed attempts are retained separately. An item is blocked or incomplete when its evidence cannot be collected; do not relabel a weaker surrogate as completion.

## Parallel lanes and gates

The numbered groups are not five serial implementation phases. N40 deliberately depends on N41, and portability does not block the local experiment path.

| Lane | Starting work after the baseline | Main ownership boundary |
|---|---|---|
| Quality and intent | N05–N20, then N43–N44 | Contracts, request blindness, eval procedures, reference-provider bindings, qualification fixtures |
| Lifecycle and execution | N03–N04, N21–N30 | Host runner, liveness/fencing, publication, quotas, network policy and isolation |
| Integration and use | N31–N38 after their dependencies | Complete manifests, clean live runs, failure propagation, repair/reuse and agent consumers |
| Portability and experiments | N08–N10, N41 early; N39–N40 and N45–N50 when ready | Exposure ledger, bootstrap, checkpoint/recovery, preregistration and final comparisons |

Do not run two writers over the same implementation files. Assign one owner for shared schemas; downstream lanes consume versioned fixtures. Agents hand off file paths, hashes, exact checks, residual limits and changed choices. Integration validates those receipts independently.

- **Gate A — usable ruler:** N20 passes before broad claims about artefact quality.
- **Gate B — controlled local cycle:** N42 passes before the next broad live comparison.
- **Gate C — comparative evidence:** N45 freezes the experiment before N46–N48 produce measurements. A measured noise floor may only change allocation through a preregistered rule or explicit amendment.
- **Gate D — adoption:** N49 decides narrowly; N50 audits. N40 is required for a cross-host resume claim, not for a local-only quality result.

## Edition 3 alignment

The plan advances bounded maker/runtime authority, frozen executable verification, provenance, minimal repair and reuse. DEC-79/DEC-80 supersede historical post-hoc judging; DEC-81 keeps domain data owned by the consuming project. The initial schedule freezes evals before starting the generator. Parallel eval writers and parallel independent requests supply concurrency without weakening that ordering; any later overlap must preserve the freeze/blindness rule under a separate measured change.

No old WP status is silently promoted by these new items. A future implementation must map evidence back to its work package and active decision. Reuse P-10 through P-13 mechanisms; do not copy their one-off orchestration bugs or describe their probes as a deployed platform.

## Open questions

The exact network enforcement mechanism, supervisor/fencing design, publication durability policy, reference-provider implementation, compatible second host and next campaign budget are implementation/experimental decisions to resolve in their named items. This plan does not preselect unmeasured solutions or invent improvement targets. Preregister thresholds and allocations with the evidence available at execution time. A blocked portability item must remain visible rather than forcing a local quality experiment to make a cross-host claim.
