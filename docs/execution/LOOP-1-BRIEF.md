## What this is, in five sentences

Endoforge is a software factory whose product is small, gate-verified capabilities (pure AssemblyScript→WASM kernels plus declarative glue) made from real technician requests without a person in the loop. Loop 0 (17 Oct 2026, `campaigns/x1-spec-study/`) ran the factory on 20 frozen requests: 19 gated, 18 shipped to the refrigeration-ai app, but only 3 were accepted by every reviewing persona as returned; the binding constraint is intent fit, not compute. The hill-climb (`docs/execution/HILLCLIMB-METHOD.md`, v2.2) is how the factory improves itself: the whole stack moves each loop, adoption is decided by a sealed oracle panel the optimised agents cannot read, and the spec itself is the incumbent to beat, not a law (DEC-75). No human is in the loop (DEC-74): you decide, record and proceed; the owner may read and veto but is not a resource you wait on. Your job is to run loop 1 end to end, under the honesty rules, and leave a record from which loop 2 can be run by someone who has never spoken to you.

## What to do (the charter's order; a plan, not a law)

If you have a better design at any step, write the departure down as a hypothesis with its reason and its test, hash the precommit for what you actually run, then run it. A departure without a record is drift.

0. **Freeze.** Create the kit. Write `receipt/freeze.json`: the working/sealed split and its seed; the canary ids and sheet hashes; sha256 of every file you will treat as fixed (`gate.mjs`, `glue.schema.json`, the incumbent briefs). Version and hash every brief you write (`briefs/<role>-v<N>.md`, listed in `receipt/briefs.sha256`). Build the incumbent manifest (factory v2 as run in loop 0, plus `--effort low`) and the challenger manifest (the all-new bundle from the charter), each as a file the runner reads.
1. **Deviation step.** A fresh agent that will not run your experiments, preferably on Codex for family independence, reads the spec and loop 0's data and proposes at least five deviations (seeds D-01..D-07 plus its own), each with: what the spec says, what the data says, the change, predicted effect, cost, one-loop test. Rank by expected gain per cost. Put the top affordable one into the design as an arm or factor. Record the whole list in `receipt/deviations.md`; carry forward what you cannot afford.
2. **Oracle criteria and canary dry-run.** Each oracle (Sonnet technician, Opus reviewer, Codex technician if usable) writes blind criteria for the 20 working requests from the raw request text, before any kernel exists, anchored by executable checks where possible; criteria are stored hashed under `work/oracle/<oracle>/` and never shown to optimiser agents. A fresh agent audits five criteria sheets for executable anchoring. Replay the three canaries through the panel: 3/3 or stop and revise the oracle protocol (slow loop, recorded) before anything else runs.
3. **Precommit, then the noise floor.** Write `PRECOMMIT.md` (hypotheses, the exact design, the panel-clean rule, thresholds, stop rules, forecasts with probabilities) and record its hash before any run. Then: incumbent twice and incumbent-without-low-effort once on the 20 development requests, interleaved and randomised (60 runs). Prediction: |Δclean| between the two identical runs ≤ 15 points (P ≈ 0.77); above 30, stop and resize. Measure tokens per request per stage.
4. **Budget decision.** From the measured cost choose: the 2^(4−1) screen by composition (stage outputs cached and corners assembled; about 160 stage-runs) if it fits the subscription windows within two days; else the four-corner design; else the sequential allocation of D-07 if its simulation on loop-0 data holds. Record the choice and the arithmetic.
5. **Run** in request-complete blocks so an early stop stays balanced; minimum 12 requests analysed. Every CLI call appends one line to `receipt/tokens.jsonl` (stage, arm, request, model, effort, tokens by kind, wall, exit, limit events).
6. **Score.** The panel scores blind (artefact sheet plus its own criteria; never the generator's reasoning). Panel-clean default: gated and the median oracle level is clean; record the strict (all clean) and lenient (none not-usable) rates too. Five all-new promotions are exercised end to end by a consumer agent in the technician frame on fresh inputs through `try.mjs` (agent-corroborated use). Score the sealed 20 once, for both manifests, as the durability baseline.
7. **Conclude.** Paired contrast with effect-size CIs (`lib/stats.mjs`: Clopper–Pearson, κ); guardrails checked against their pre-registered bounds; Brier-score every forecast; write `receipt/DECISION.md` (adopt / no evidence at this n / void, and why); merge winning deviations into the spec (version bump, errata entry, decision record) or record them as lost; append lessons; write the hand-off; commit.
