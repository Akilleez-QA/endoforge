# Execution-plan reconciliation (2026-10-17, after the probes and the X1 pilot)

> Written 2026-10-17, later the same day as `CRITIQUE-2026-10-17-plan.md`. That critique fixed the plan before any probe result was read. This one reconciles the planning documents with what was measured on the same day: six probes (P-01 to P-06), the subscription-only model-term probe (P-04b), the X1 dark-factory pilot (20 requests → 19 gated kernels), the persona review (43 → 41 verdicts), the extended promotion rule (gated and persona-accepted) and the delivery of the kernels to the refrigeration-ai repository. It then applied the changes in place; this file records what was stale, the evidence, and what changed where.

Read in full: `docs/CONVENTIONS.md`; `docs/execution/LESSONS-LOG.md` (L-01 to L-14); R12 §7 (probe rows including P-04b and the X1 pilot row); R16 DEC-64 to DEC-71; `campaigns/x1-spec-study/receipt/{notes.md,factory-summary.json,persona-review-summary.md,summary.json}`; `experiments/P-04b-bare-api-model-term/RESULT.md`; `CRITIQUE-2026-10-17-plan.md` (the shape this file follows); the three hand-over notes of the sibling sessions (P-04b, capabilities delivery, promotion rule). Nothing under `experiments/`, `campaigns/` or the refrigeration-ai repository was changed.

The independence is limited as before: the same model family wrote the plan, ran the pilot and wrote this reconciliation, in a fresh context.

Labels: every number below is **Recorded (probe)** when it comes from a probe `RESULT.md` or R12 §7, **Pilot (not a registered result)** when it comes from the X1 pilot's receipts, **Derived** when it is arithmetic on those, and **Proposed** when it is a rule. Request text stays out of this file (DEC-68); capabilities are named by id only.

Classes:
- **stale**: a document described a design or a state that the day's work has replaced (a human specifier, an API arm, an unmeasured assumption now measured).
- **gap**: a measured finding had no home in any planning document.
- **note**: record it and decide.

## Stale designs and gaps, with the change applied

### R1 (stale). C01 described a human specifier; the pilot ran, and DEC-71 governs, an agent specifier
- **Evidence:** C01 §4 "S — Human specifier … no model assistance"; §10 "12–20 person-hours". R16 DEC-71: "No person writes contracts … C01 and R14 X1 need rewriting to this design before registration." `receipt/notes.md`: rater 1 is a fresh agent per request; rater 2 a fresh blind agent; the person confirms the question.
- **Failure scenario:** C01 is registered as written and a person hand-writes 20 contracts, measuring a design the owner has withdrawn; or the pilot's numbers are read into a precommit that describes a different arm.
- **Change (applied):** C01 rewritten for the agent specifier: arm A (fresh agent per request, blind rater-2 agent, person confirms the question); budget in tokens and 1–2 person-hours; a new §16 "Pilot (not a registered result)" with every pilot number labelled; §17 "What registration still requires" (named author and reviewer, the tightened residual rule and a clustering procedure in the rubric, a fresh run, per-id person confirmation, a fresh rater per id, and the rung-4 path outside C01). R14 X1's design row says the same. The DP-6 bands, the 20 % threshold and the extension rule are unchanged.

### R2 (stale). C01's "what X1 decides" assumed the hard part was specification time; the pilot measured minutes
- **Evidence:** C01 §2 rival "specification cost dominates"; R15 RISK-11. Pilot: 20/20 contracts rubric-complete, median 95 s, p95 147 s, 20/20 under 600 s (`summary.json`); 20/20 underdetermined by rater 1, 9/10 by the blind rater; residual count disagreed on 7/10 blind items (L-11).
- **Failure scenario:** a registered X1 passes trivially on completeness while every contract answers a question the requester did not ask; the primary cannot see it.
- **Change (applied):** C01 §3 now states what X1 decides (can an agent specifier produce contracts at all; residual thickness) and what it hands to X2 (whether the contract is the capability wanted: C02's grading and the persona stage); the rival gains its agent-specifier form (complete-looking contracts by assumption); the parity rule stops the run if completeness disagreement on the blind half exceeds 2 of 10; κ is reported with its no-variance caveat and per-field agreement alongside.

### R3 (gap). The 20 contracts, their frozen tests and the persona findings had no home in C02
- **Evidence:** C02 §6 "Task set SHA-256 TBD at freeze"; nothing cited the pilot. `factory-summary.json` carries a contract and test hash per id; `persona-review-summary.md` carries 41 verdicts and two rejections; the residual-counting rule was the commonest rater disagreement (7/10).
- **Failure scenario:** C02 synthesises 100 fresh residuals and grades them with a counting rule that the pilot already showed two raters apply differently; the one set of contracts with persona verdicts attached is never graded against them.
- **Change (applied):** C02 Summary, header, §5 (residual-counting rule: assumption-pin and boundary rows counted separately; a test format that cannot carry a needed value is an evaluator defect), §6 (the 20 as a labelled seed stratum of pass 1, with the 41 verdicts and the two rejections, reported separately from the 80 fresh tasks), §8 (the two rejections and CC-001 among the 10 calibration evaluators), Open questions (correlated case: the same agent wrote contract, tests and kernel; "determinate given the stated assumption" as a seed label), Edition 3 alignment, Sources. WP08 inputs, deliverable (7) and acceptance (f) say the same.

### R9 (gap). Evaluator totality did not cover the test format
