# Requirements

These requirements describe implemented behavior, not authority to execute work.
Verification methods: T = test; I = inspection. Commands run from the repository root.
The selected tests cover these behaviors; they do not qualify live model services.
The core includes the evaluator and gates in `core/engine/`; host callbacks supply
candidate operations. Local agent execution pools live in `core/runtime/` and are
invoked explicitly by workflow callers. The Python import boundary permits the engine adapter to use the core
ledger, `pathlib`, and `sys` without loading it through `import core`.

| ID | Requirement | Rationale | Verification |
|---|---|---|---|
| REQ-CORE-001 | The Python core shall import only its scoped standard library allowlists and shall not load concrete integrations on import. | Keep execution outside the lifecycle model. | T: `make core-test`; `tests/test_endoforge_core_boundary.py`. |
| REQ-LIFE-001 | The lifecycle shall refuse transitions outside its legal state graph. | Prevent skipped lifecycle stages. | T: `make core-test`; `tests/test_endoforge_lifecycle.py`, `TransitionTests`. |
| REQ-LIFE-002 | Qualification shall require a passing receipt for the exact candidate under the frozen oracle. | Bind qualification to independently checked bytes. | T: `make core-test`; `tests/test_endoforge_lifecycle.py`, `TransitionTests`. |
| REQ-LIFE-003 | Applying a transition shall require a decision bound to the current proposal digest and shall refuse reused decisions. | Prevent stale or replayed authorization references. | T: `make core-test`; `tests/test_endoforge_lifecycle.py`, `DecisionTests`. |
| REQ-LIFE-004 | Generation shall not confer qualification or activation. | Separate candidate production from acceptance. | T: `make core-test`; `tests/test_endoforge_lifecycle.py`, `GenerationGrantsNothingTests`. |
| REQ-LIFE-005 | Artifact identity shall distinguish generation inputs, candidate bytes, and qualification receipt. | Preserve evidence identity across stages. | T: `make core-test`; `tests/test_endoforge_lifecycle.py`, `IdentityTests`. |
| REQ-LEDGER-001 | Evaluation shall refuse changes to frozen evaluator components before judging. | Prevent the candidate's checks from changing during evaluation. | T: `make ledger-test`; `core/ledger/test_frozen.py`, `FrozenTests.test_every_component_change_refuses_before_judging`. |
| REQ-DOCS-001 | Repository checks shall validate local Markdown link targets and source digests. | Keep navigation and supplied source evidence reproducible. | I: `make check`; inspect `tools/check-docs.py` and `sources/SHA256SUMS`. |
| REQ-DOMAIN-001 | The engine shall delegate named domain invariant checks to caller callbacks without importing domain implementations. | Foundations own domain logic; engine evaluation remains reusable. | T: `make engine-test`; synthetic identity invariant in `core/engine/evaluator.test.mjs`. |
| REQ-ISO-001 | The runtime shall execute the real frozen evaluator and gates in separate V8 workcells, with one active job per workcell, FIFO dispatch, at most the configured size, and default size `os.availableParallelism()`, on Node 22 and Node 26. | R02 assigns parallel work to separate isolates; P-15/P-17 support core-count throughput sizing. | T: `make isolate-test`; native parity, concurrency 1/4/16, and defaults tests; CI runs Node 22 and 26. |
| REQ-ISO-002 | Each workcell shall receive configurable positive old and young generation heap limits through Node `resourceLimits` in thread mode or `--max-old-space-size`/`--max-semi-space-size` in process mode; defaults shall be 128 and 16 MiB. Conflicting heap command-line overrides shall be refused. | Bound each JavaScript heap independently. | T: `make isolate-test`; heap exhaustion and validation tests. |
| REQ-ISO-003 | The runtime shall replace an exited workcell after exit, return `outcome_unknown`/`limit` in thread mode or `rejected` with reason `heap`/`wasm_memory` in process mode for confirmed memory breaches, and continue queued and independent jobs without retrying the lost job. | A lost acknowledgment cannot establish a verdict. | T: `make isolate-test`; heap, WASM and exit tests. |
| REQ-ISO-004 | The host shall append candidate-bound receipts for every evaluated batch through the existing ledger validator and hash chain, including failed receipts for confirmed process memory breaches and inconclusive receipts for other lost workcells. | Preserve one durable evidence chain across isolates. | T: `make isolate-test`; shared ledger, returned hashes, tamper detection, heap, WASM and exit tests. |
| REQ-ISO-005 | `close()` shall refuse new submissions, drain accepted jobs and receipts, and terminate all workcells; repeated calls shall return the same promise. | Permit orderly caller shutdown. | T: `make isolate-test`; concurrency 1/4/16 tests. |
| REQ-ISO-006 | Workcells shall enforce `wasmMemoryMaxMb` (default 64 MiB, integer 1–4096) on each WASM linear memory independently of the JS heap. Checked constructors, compilation and instantiation shall reject untrusted module memories without a declared maximum and all initial/maximum declarations above the cap, preserve existing declared maxima, and prevent JS or internal instruction growth past the ceiling. A breach shall terminate only its cell, return `ERR_WORKCELL_WASM_MEMORY_LIMIT` with the mode-specific status/reason in REQ-ISO-003, replace the cell after exit, and preserve concurrent accepted/rejected verdicts. Unsupported memory-bearing binaries and externally compiled modules shall fail closed. | P-16 shows that a JS heap flag does not cap WASM memory; use native maxima plus instruction checks. | T: `make isolate-test`; WASM declaration, API path, internal growth, start, swallowed-trap, neighbor/replacement and cap-boundary tests. |
| REQ-ISO-007 | `isolation` shall select `thread` (default) or one forked Node process per workcell. Process mode shall use writable cgroup v2 delegation when available, setting per-child `memory.max`, `memory.oom.group=1`, `cpu.max` and `pids.max`; otherwise results shall record `cgroup: "unavailable"` while retaining V8 limits. No root privileges shall be required. | Contain fatal V8 exits without requiring OS delegation. | T: `make isolate-test`; process breach, compile gate, fallback, parity and chain tests. I: cgroup helper; delegated enforcement is unmeasured locally. |
| REQ-X1-001 | X1 G1–G7 shall run through the real evaluator in thread/process pools, bind frozen checks and compiled source, and preserve X1 test/glue decisions. Compilation shall occur on the supervisor with a timeout. | Replace the experiment-only port without changing acceptance. | T: `make pipeline-test`. |
| REQ-GEN-001 | Generation shall invoke an environment-configured Codex command twice, durably freeze contract/tests before code, refuse drift and premature code, and return candidate bytes without conferring promotion. The adapter shall not read or copy auth files. | Close the synthetic-generation gap while retaining the freeze boundary. | T: `make pipeline-test`; labelled fake Codex script. |
| REQ-GEN-002 | The implementation request shall carry the G7 glue rules (number precision, code tables, boolean labels, trap entries, export and arity coverage) and a conforming glue template; G7 itself is unchanged. | Give generation the acceptance contract up front instead of discovering it at G7. | T: `make pipeline-test`; generator rules test. |
| REQ-GEN-003 | Generation shall by default resume the specification session for implementation (`ENDOFORGE_CODEX_SESSION=resume`, or `fresh`), select reasoning effort by `ENDOFORGE_CODEX_EFFORT` (`auto` gives `low` when the requester's words are at most 400 characters, `default` leaves the client setting, other values pass through), instruct the client not to explore or run commands, and keep the durable freeze between the two turns. | Cut generation latency without weakening freeze-before-code. | T: `make pipeline-test`; warm-session test. |
| REQ-GEN-004 | The implementation request shall state that the compiler runs with `--noAssert` and require every expectError case to trap with an explicit `abort()` or `throw` instead of `assert`; G4 and compiler flags are unchanged. | P-24: 43 of 45 G4 refusals used `assert(`, which `--noAssert` deletes. | T: generator rules test; confirmation run P-27. |
| REQ-PROMOTE-001 | Local promotion shall issue a persisted qualification decision only for the exact candidate, frozen oracle, verified receipt hash and chain with two complete passing pool rounds and all seven X1 gates passing. Any mismatch shall refuse. | Supply the executable interface a future POODO host can call without claiming POODO authority. | T: `make pipeline-test`; thread/process promotion and refusal tests. |
| REQ-ISO-008 | Only supervisor configuration shall authorize supplying an omitted WASM maximum, by a named complete-binary SHA-256 match and positive integer page cap within the workcell ceiling. Candidate inputs shall not grant trust. Existing maxima and all other guard checks shall remain enforced. The supervisor shall record the configured name, digest and cap in results and durable receipt observations, including worker losses. | Permit pinned compiler helpers while retaining fail-closed candidate checks and auditable policy. | T: `make isolate-test`; trusted compiler native cap, API paths, policy validation, candidate forgery and replacement tests in both modes. |
